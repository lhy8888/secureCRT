# 0.4：SSH跳板与转发

本轮包含0.3的SFTP、日志与Hex。目标平台为Windows 10/11；以下运行证据来自Linux本地真实SSH/SFTP服务、TCP与Qt离屏窗口。

## 单级跳板

目标会话可引用一个已保存的SSH会话。先建立跳板，再通过其direct-tcpip通道连接目标。每端独立验证自己的known_hosts、用户名、密码或私钥；不把目标密码用作跳板密码，不转发Agent。界面分别显示连接跳板/连接目标。

未知密钥、认证拒绝、失败或取消会关闭已经建立的连接。Worker完成登录或退出时移除凭据选项；配置v3仅保存跳板会话名称，兼容读取v1/v2，不保存密码或私钥内容。Python内存副本无法保证擦除。

当前只支持单级。缺失、非SSH、循环/嵌套跳板引用会被拒绝。没有多跳拓扑、共享已打开跳板会话、跳板MFA或自动恢复。

## 本地、远程与SOCKS转发

“SSH隧道”窗口提供建立、列出与停止监听。所有监听请求固定127.0.0.1，端口0自动分配；每会话最多16个监听，待处理请求最多8项，建立有15秒期限。单个转发错误不关闭SSH终端。

L的目标从SSH服务端访问；R的目标从本机访问；SOCKS的目标按请求从SSH服务端访问。关闭管理窗口保留监听。停止监听只关闭新连接入口，已建立流可能继续；断开SSH关闭全部流和依赖跳板。远程服务器可能覆盖监听地址请求，不能将客户端请求当作服务端实际网卡绑定的证明。

SOCKS没有单独代理认证，本机其他用户可能访问回环监听。只验收SOCKS5无认证IPv4握手及字节往返；域名、IPv6、不同服务器和长期并发未验收。没有转发模板持久化、复制、禁用、导入或本地程序启动。

## 验证

- 跳板与目标独立密码、两端未知密钥分别拒绝；交互与SFTP经跳板共用认证，关闭两端；取消卡在目标握手中的连接并移除凭据选项。
- 真实TCP二进制数据经过本地/远程转发；SOCKS5握手后真实收发；绑定冲突不破坏已有监听；停止监听及断开SSH释放端口；16个监听的容量限制及全部关闭。
- Qt隧道窗口建立、实际TCP收发、停止、隐藏与断开清理。新界面采集使用安装后的0.4包、本地两级SSH服务与PTY，非界面示意图。
- 对历史SFTP短读场景补充真实服务故障注入：每次1–3字节响应仍完整往返；提前EOF拒绝提交，原目标保持且临时文件清理。不是SecureCRT原始缺陷复现。
