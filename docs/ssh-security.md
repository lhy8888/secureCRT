# SSH安全、身份与主机信任（0.7）

在“会话选项 → SSH安全策略”配置算法顺序、Strict KEX、压缩及重协商阈值。“工具”菜单提供主机密钥管理、身份密钥工具和当前SSH协商诊断。跳板与目标各用自己的会话设置，分别验证。

## 默认策略与旧设备

默认只提议当前运行库可用的现代算法：优先Curve25519等SHA-2密钥交换，ChaCha20-Poly1305、AES-GCM/CTR，SHA-2 MAC，Ed25519/ECDSA/RSA-SHA2签名。ML-KEM混合交换仅在运行库实际支持时出现，不把可选依赖缺失说成已支持。

列表留空使用推荐顺序；可用“选择…”勾选及上下移动，或填写逗号分隔的精确名称。没有共同算法就连接失败，不会自动扩大列表。`ssh-rsa`是SHA-1签名算法名；RSA公钥仍可使用RSA-SHA2签名，诊断中分开显示公钥格式与协商签名。

Strict KEX默认“必须核验”，不支持或无法确认时在用户认证前断开。旧服务器可在**自己的会话**选“兼容：尽量协商”。旧算法许可只允许显式选择group14-SHA1、AES-CBC、HMAC-SHA1和RSA-SHA1，不会自动加入默认列表。GUI每次连接前展示目标/跳板的兼容设置，默认取消；无界面执行还需`--allow-legacy-ssh`。group1、RC4和MD5不在可选列表中。

Strict KEX与实际KEX名称使用针对AsyncSSH 2.24.1测试的元数据适配器。依赖锁固定此版本；更换版本前需验证适配器，否则“必须核验”模式拒绝认证。诊断缺失字段保持未知，不推断安全通过。没有FIPS认证声明。

## 压缩与重协商

默认关闭压缩。唯一可选压缩是认证成功后启用的`zlib@openssh.com`，不允许认证前的`zlib`。默认重协商阈值1 GiB/3600秒；可配置1024字节至64 GiB、1秒至24小时。字节阈值、时间阈值触发真实NEWKEYS且不中断二进制流已有回归，仍需按自己的设备和负载验证。

## 主机密钥与证书CA

未知或变化的主机密钥直接拒绝；不提供自动接受。主机密钥管理可以：

- 读取、导入、导出OpenSSH `known_hosts`，显示主机模式、别名、标记及SHA-256指纹。
- 添加普通主机公钥、`@cert-authority`主机CA或`@revoked`吊销项，删除选中项，检查本地名称/端口匹配。
- 处理逗号分隔别名、通配模式及OpenSSH散列主机名；非22端口写作`[host]:port`。

保存信任前必须勾选已通过独立可信渠道核对指纹和范围；预览期间文件被其他窗口改动则拒绝覆盖。导入不连接网络。CA信任范围、证书主机名、有效期与吊销均参与真实SSH校验；没有OCSP、CRL下载或X.509身份体系。添加框拒绝私钥，检测到常见私钥粘贴会立即清空。

公钥库最多1 MiB、5000条。锁、修订号及上次有效备份与会话存储共用，但不能协调不遵守锁协议的外部工具，也不提供跨机器事务。核对错误的CA或通配范围会扩大信任，应以实际资产范围保存。

## 身份密钥与用户证书

身份工具生成Ed25519、RSA 3072/4096、ECDSA P-256/P-384。默认加密OpenSSH私钥，bcrypt KDF 128轮、AES-256-CTR，新口令至少12字符；空口令必须明确选择未加密生成。生成与检查在后台线程执行，口令输入框随操作清空，输出仅有公共指纹、公钥或路径。

新私钥及`.pub`不覆盖现有文件；同卷硬链接实现单文件原子不覆盖，普通NTFS可用，文件系统不支持时失败。第二文件发布失败时清理本次发布的自有文件，不覆盖竞争者文件；两文件不是掉电原子事务。POSIX新文件0600，Windows继承目录ACL，请放在自己的受限目录。这不是Windows凭据库、DPAPI或Python内存擦除保证。

显式私钥输入限制1 MiB，OpenSSH bcrypt参数先做盐长度和1–1024轮上限检查，再进入解密。其他受支持格式仍由运行库解析，尚无PPK转换工具。

会话身份页可分别选择私钥与OpenSSH**用户证书**。当前支持一个显式私钥配一个证书；匹配公钥、用户证书类型及有效期先在本机检查，服务器再验证CA/用户名。无效证书拒绝连接，不静默退回裸公钥。CLI可用`--identity-file identity --certificate-file identity-cert.pub`，没有CLI口令参数；加密私钥的交互解密走GUI。独立证书与Agent/硬件令牌组合尚未支持。

## 诊断与配置

当前SSH标签可打开协商诊断，显示客户端/服务器版本、双向cipher/MAC/压缩、Strict KEX、实际KEX、主机签名算法和SHA-256指纹；可导出JSON。它不包含密码、私钥、认证回答或原始数据包，也不是完整的协议抓包和失败阶段追踪器。对端版本文本的控制字符在界面中转义。

会话JSON及Harbor原生XML写入schema 5，可读取旧schema 1–4；安全设置可经批量编辑及SSH默认模板管理。配置只保存算法、阈值和密钥/证书路径等元数据，文件内容与口令不随导入导出传播。

验收证据见本版本的`artifacts/validation-0.7.md`及`tests/test_ssh_security*.py`、`tests/test_key_tools.py`。这些是Harbor自己的回归场景，不能表示已复现并修复SecureCRT历代所有私有实现问题，或证明比商业产品整体更安全稳定。
