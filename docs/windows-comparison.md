# Windows 与 SecureCRT 9.7.4 同机对照

这是可重复的测试规程，尚无实机对照结果。先在 SecureCRT 的“关于”中确认完整版本为 9.7.4，并保留 Harbor 的 BUILD-INFO.json 与 ZIP SHA-256。测试需使用你已有的正版 SecureCRT，不分发其程序或字体。

记录 Windows 10/11 的版本、显示器与缩放、终端字体字号、USB 适配器型号/驱动版本、数据位/校验/停止位/流控、SSH 服务端及算法。两款程序设置相同行列、历史大小和日志策略；每组重复三次并交换先后顺序，记录原始结果。

## 同机工作负载

| 场景 | 操作与记录 | 当前证据 |
|---|---|---|
| 常用 SSH | 同一实验服务器登录、连续输出、窗口缩放、复制中文；记录丢字、异常断开、退出原因 | Harbor 有本地自动测试；同机对照待执行 |
| 安全认证 | 未知/变更主机密钥、加密私钥、两轮 MFA、多行提示、取消认证 | Harbor 有真实服务测试；双方实机结果待填 |
| 终端 | 相同 UTF-8/GB18030 文件、256/24位色、中文宽字符、应用光标、备用屏幕；逐屏比对 | 完整 TUI/IME 对照待执行 |
| 批量命令 | 两个无生产权限的实验会话，确认预览目标；取消等待后验证后续步骤没有发送 | Harbor 有实际 Qt + SSH 测试 |
| SFTP/隧道 | 同一文件 SHA-256、传输中取消、监听冲突、断开后端口释放 | Harbor 有故障注入；对照待执行 |
| 实体串口 | 同一适配器、同一回环、相同波特率，分别运行；记录实际字节、错误、驱动异常 | 使用 HARDWARE-TESTING.md；尚无用户实测报告 |
| 长期资源 | 固定输出速率、日志配额与窗口大小；至少运行目标时限后比较资源趋势和异常 | 云端持续测试不能代替 Windows/实体 COM 对照 |

同一个 COM 必须按顺序给两款客户端使用，不能同时占用。Harbor 的二进制回环检测器验证 Harbor/驱动/线路，不能作为 SecureCRT 的收发结果。SecureCRT 需用其自身功能和同等可核对的输入/接收数据单独记录。没有共同数据源、相同节奏和可验证输出时，不据资源数值判定谁更稳定。

## 资源采样

分别启动一个 HarborTerminal.exe 和一个 SecureCRT.exe 后，在包目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Measure-HarborComparison.ps1 -Target Both -Seconds 600
```

顺序测串口时，可分别用 `-Target Harbor` 与 `-Target SecureCRT`，时长一致。脚本只读取选定进程的工作集、私有内存、句柄、线程和累计 CPU 时间，不读取密码、终端正文、网络地址或设备流量，不控制客户端。报告写入本地 Diagnostics 唯一子目录。

`completed` 仅表示采样到时限；`process_ended` 不判断是用户关闭还是崩溃；均不表示协议测试通过。CPU 区间占用可由相邻累计 CPU 毫秒差 / 采样间隔毫秒计算；按全机容量比较还需除逻辑处理器数。进程初始化与缓存会影响工作集，应比较预热后的趋势和稳定区间。

## 回传结果

保留 Diagnostics 下 JSON/JSONL，以及：测试场景、双方准确版本、设置、起止时间、预期输出与实际差异。设备清单可能含硬件序列号，分享前可脱敏。未执行的项目填“未执行”，时间不足填“未完成”；不要写成通过。当前没有可支持“比 SecureCRT 9.7.4 更安全稳定”的同条件结果。
